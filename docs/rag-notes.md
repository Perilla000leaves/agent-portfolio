# 从代码规则到可检索知识库

记录把「写在代码里的规则」编译成向量知识库时踩到的坑。具体业务与厂商名已省略，
结论保留到可以复用的粒度。

## 为什么不能直接索引源码

规则模块导入时通常有副作用：连缓存、拉远端词表、构建匹配自动机。一个只想「读一份数据」
的构建脚本，会因为 `import` 变成启动半个服务。

所以构建链的第一步是**静态解析**（`ast.parse`），只取字面量，不执行：

- 能取到：集合 / 列表 / 元组里的字符串常量；
- 取不到：表达式（并集、变量引用、函数调用）——这类词要人工补，不能假装拿到了；
- 配套规则：某个字段里的词，只有判定表达式**真的引用**了它才算数。写在字段里但判定
  没用到，导出只会虚增词频。

## 词角色：同一个词，在不同标签里不是一回事

规则表达式决定了词的作用，盲目统计会把反例算成占用：

| 角色 | 表达式形态 | 含义 |
|---|---|---|
| 触发词 | 默认 | 命中即参与判定 |
| 扣除词 | `found - {…}` | 命中只是不计入证据，不否定标签 |
| 否决词 | `not (found & {…})` | 命中即推翻该标签 |
| 开关词 | `A if condition else B` 的条件段 | 全量里通常只有个位数条 |

只认这三种结构。语义等价但写法不同的（例如 `'x' not in found_text`）识别不出来，
标记为 `complex` 交人工复核——**宁可漏判也不误判**，因为误判会静默改变标签的命中口径。

## 分块：不设边界就只能被截断

向量库的切片配置属于建库参数，`update` 接口通常不支持改切片方式，**想换策略只能重建库**。
实测到的几条约束：

- **分隔符长度有限**（例如每个不超过 10 字节，中文按字节算）：`【标签档案】` 这种 6 个汉字
  会直接被拒，必须换成短 ASCII 标记；
- **分隔符会被从切片正文里删掉**：所以标记既要在正文里唯一，又不能承载信息；
- **必须关闭「合并小切片」**：否则刚切开的档案会被重新合并成固定长度，标记白写；
- **不设分隔符时**：无论块长参数填多少，实际都切在 2000 字上下——像是被向量模型的输入上限
  卡住，而不是按配置切。

结论：短标记 + 关闭合并 + 一条档案一个块，是这个场景里唯一稳定的组合。

## 超长词表：代表词 + 续块

一条标签可能有上千个触发词，全列进一个块会超长被截断，而**截断是静默的**——
检索时才发现某个词检不到。

做法是：

1. 档案块只列前 N 个代表词（按共用度排序）；
2. 其余词按字符预算拆成若干「词表续」块，块首重复写标签名、应用与处置；
3. 编译后用断言校验**源词表与块内词的集合完全相等**，一条都不能少。

这个校验是构建链里最便宜、最有效的一步：它把「悄悄丢词」变成「构建失败」。

## 一个运维坑：删文档会把库弄坏

在某个库里删掉一份文档之后，再导入的文档虽然解析成功、切片也写进了库，但检索恒定返回空
（控制台的知识检索同样为空）。换文本、换策略、清空所有文档重传都无效，**新建一个同名库导入
同一份文本就正常**。

所以遇到「检索恒空」，不要反复删文档试，直接重建库。另外，切片策略归属于单个库，把 A 库的
策略配置传给它自己以外的库会报错。

## 与检索侧的分工

知识库只负责「给出相关档案」，判断留给模型；数字留给工具：

| 层 | 负责 | 不负责 |
|---|---|---|
| 工具 | 注册查询、词频统计（从切片现算） | 语义判断 |
| 知识库 | 档案内容（应用 / 处置 / 可替换性 / 词角色） | 统计 |
| 模型 | 同一语义判断、合并还是新建、词该作触发还是反例 | 数数 |
| 提示词 | 判断标准、输出格式 | 任何事实数据 |

由此得到两条硬约束：**不提供「生成关键词」这类工具**（生成必须由模型做，包成工具就退化成
模板转发），以及**要求模型不写自己拿不到的数字**。
